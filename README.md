# Donation Email Pipeline

Автоматика подяк донорам KSE Foundation: щодня забирає нові донати з Zoho CRM у Notion, а після вашого схвалення створює готові чернетки листів у Gmail.

**Листи ніколи не надсилаються автоматично.** Скрипт створює лише чернетки — останнє слово завжди за людиною.

---

## Як це працює

```
Zoho CRM  →  Notion (таблиця донатів)  →  людина ставить ✅ Approved  →  чернетки в Gmail  →  сповіщення в Telegram
            ↑ fetch_donations.py                                        ↑ send_emails.py
            ~10:00 за Києвом                                            ~16:00 за Києвом
```

### Крок 1. Збір донатів — `fetch_donations.py`

Забирає з Zoho донати за останні 7 днів і додає їх у Notion.

- Вікно у 7 днів, а не в 1: якщо запуск зламається або GitHub його затримає, наступний підбере пропущене.
- Дублікати не створюються — кожен донат звіряється за `Zoho ID`, а якщо його немає, то за поштою і точним часом донату.
- Українські імена перекладаються латиницею. Винятки для відомих донорів прописані в `NAME_OVERRIDES` у [fetch_donations.py:78](fetch_donations.py#L78) — наприклад, Тимофій Милованов пишеться "Tymofiy Mylovanov", а не "Tymofii".
- Нові рядки з'являються з порожньою галочкою **Approved**.

### Крок 2. Ваше схвалення (вручну, в Notion)

Відкрийте таблицю, перегляньте нові донати і поставте галочку **Approved** там, де лист доречний. Скрипт бере лише схвалені рядки.

### Крок 3. Чернетки листів — `send_emails.py`

Бере рядки, де **Approved ✅** і **Draft Created ⬜**, і створює чернетки.

| Сума донату | Умова | Від кого | Підпис |
|---|---|---|---|
| до $100 | лише якщо статус донора **New** | sdenysenko@kse.org.ua | Світлана |
| $100 – $999 | якщо цьому донору не писали останні 60 днів | sdenysenko@kse.org.ua | Світлана |
| від $1000 | завжди | president@kse.org.ua | Тимофій |

Рядки без email пропускаються.

Після створення чернетки скрипт ставить у Notion галочку **Draft Created** і дату в **Email Sent At** — щоб той самий лист не створився двічі.

### Крок 4. Сповіщення

Коли всі чернетки готові, бот пише в Telegram-групу і тегає Світлану. Якщо чернеток нема — мовчить.

### Крок 5. Відправка (вручну)

Чернетки з'являються в Gmail у папці "Чернетки". Їх треба переглянути і надіслати руками.

---

## Розклад

Обидва скрипти запускає GitHub Actions — файл [.github/workflows/daily.yml](.github/workflows/daily.yml).

| Завдання | Розклад (UTC) | Приблизно за Києвом |
|---|---|---|
| `fetch-donations` | 04:40 | ~10:00 |
| `send-drafts` | 13:00 | ~16:00 |

**Чому час дивний:** GitHub не запускає завдання вчасно. Вимірювання на цьому репозиторії показали затримку від 1 до 4 годин, у середньому близько 2 годин 20 хвилин. Тому збір поставлено на 04:40 UTC — з типовою затримкою він і потрапляє близько 10:00 за Києвом.

### Запустити вручну

1. Відкрийте репозиторій на GitHub → вкладка **Actions**
2. Ліворуч виберіть **Donation Email Pipeline**
3. Кнопка **Run workflow**, у списку `job` виберіть `fetch` або `send_drafts`
4. Натисніть зелену кнопку **Run workflow**

Там же видно логи кожного запуску — зручно, коли щось пішло не так.

## Таблиця в Notion

Скрипти очікують саме такі назви колонок. Якщо перейменувати колонку в Notion — скрипт зламається.

| Колонка | Тип | Хто заповнює |
|---|---|---|
| Donor Name | Title | fetch |
| Donor Email | Email | fetch |
| Donation Amount | Number | fetch |
| Donation Date | Date | fetch |
| Donor Status | Select | fetch (New / інше — зі Zoho) |
| Designation | Text | fetch |
| UTM | Text | fetch |
| Zoho ID | Text | fetch (захист від дублікатів) |
| **Approved** | Checkbox | **людина** |
| Draft Created | Checkbox | send |
| Email Sent At | Date | send |

## Як змінити текст листа або підпис

Усе в одному файлі — [send_emails.py](send_emails.py):

- **Підписи** — `SVITLANA_SIGNATURE` і `TYMOFIY_SIGNATURE` вгорі файлу, [рядки 26-42](send_emails.py#L26-L42). Це готові блоки HTML: `<br>` — перенос рядка, `<p>...</p>` — абзац із відступом.
- **Текст листа** — змінна `html_body` у функції `create_draft`, [рядок 112](send_emails.py#L112). Текст однаковий для обох відправників.
- **Тема листа** — `subject`, [рядок 111](send_emails.py#L111).
- **Пороги сум** — `if amount < 100` і `elif amount < 1000` у функції `main`.
- **Інтервал у 60 днів** — `timedelta(days=60)` у функції `was_emailed_recently`.

Після зміни файл треба закомітити і запушити в GitHub — інакше автоматичний запуск і далі працюватиме зі старою версією.

## Ключі доступу

Жодних паролів у коді немає. Усе лежить у GitHub → **Settings → Secrets and variables → Actions**:

| Секрет | Для чого |
|---|---|
| `ZOHO_CLIENT_ID`, `ZOHO_CLIENT_SECRET`, `ZOHO_REFRESH_TOKEN` | доступ до Zoho CRM |
| `NOTION_TOKEN`, `NOTION_DATABASE_ID` | доступ до таблиці Notion |
| `GMAIL_SVITLANA_CLIENT_ID`, `..._CLIENT_SECRET`, `..._REFRESH_TOKEN` | пошта Світлани |
| `GMAIL_TYMOFIY_CLIENT_ID`, `..._CLIENT_SECRET`, `..._REFRESH_TOKEN` | пошта Тимофія |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `SVITLANA_TELEGRAM_USER_ID` | сповіщення |

Gmail-доступ виданий лише на створення чернеток (`gmail.compose`) — надсилати листи від вашого імені скрипт технічно не може.

## Якщо щось пішло не так

**Чернетки не з'явилися.** Перевірте в Notion, чи стоїть **Approved** і чи порожня **Draft Created**. Потім гляньте логи в Actions — там видно причину пропуску кожного рядка.

**Донат не потрапив у Notion.** Або він поза вікном у 7 днів, або скрипт вважає його дублікатом. У логах шукайте `Skipping duplicate donation`.

**Запис продублювався.** Найчастіша причина — у таблиці немає текстової колонки `Zoho ID`, і звірка йде за слабшими ознаками. У логах буде `WARNING: the Notion database has no 'Zoho ID' property`.

---

## Тонкощі, про які варто знати

- **Перевірку часу вимкнено.** У [send_emails.py:19-21](send_emails.py#L19-L21) закоментовано код, який дозволяв запуск лише о 16:00 за Києвом. Зараз скрипт працює о будь-якій годині — інакше через затримки GitHub він майже ніколи б не спрацьовував.
- **Коментар про 13:00 і 14:00 UTC** у тому ж файлі застарів: у розкладі зараз лише один запуск, о 13:00 UTC.
- **Тема листа однакова** для всіх донорів і не залежить від суми.
- **Запасний спосіб запуску.** Якщо колись знадобиться запуск точно о 10:00, його доведеться тригерити ззовні GitHub — подія `repository_dispatch` для цього вже налаштована у файлі workflow.

## Локальний запуск

Зазвичай не потрібен — усе працює на GitHub. Але якщо треба перевірити зміни:

```bash
pip install requests pytz translitua==1.3.2 google-auth google-auth-oauthlib google-api-python-client
```

Далі треба виставити всі змінні середовища зі списку секретів вище. Для збору донатів є безпечний режим — він лише показує, що зробив би, нічого не записуючи:

```bash
DRY_RUN=1 python fetch_donations.py
```

У `send_emails.py` такого режиму немає: запуск створить справжні чернетки в Gmail і проставить галочки в Notion.
